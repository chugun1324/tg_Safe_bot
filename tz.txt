
1. Введение
1.1. Название проекта

ArtSecure: Платформа в Telegram для безопасной передачи художественных работ (комиссий) от художников к заказчикам с минимизацией рисков кражи интеллектуальной собственности (ИС).

1.2. Цель проекта

Создать MVP (минимально жизнеспособный продукт) Telegram-бота, который автоматизирует процесс заказа, оплаты и передачи работ художников, обеспечивая защиту от кражи через инструкции по использованию disappearing media, водяные знаки и escrow-подход.
Обеспечить удобный интерфейс для художников и заказчиков, монетизацию через комиссии и подписки.
Решить проблему: Художники часто сталкиваются с кражей работ до оплаты; бот минимизирует это через Telegram-фичи (protect_content, disappearing media) и координацию.

1.3. Обзор проекта

Бот координирует взаимодействие: регистрация, создание заказов, обсуждение, предпросмотр (low-res с водяными знаками), оплата (с escrow), финальная передача через приватный чат с disappearing media.
Аудитория: Художники (иллюстраторы, дизайнеры, NSFW-арт и т.д.) и заказчики по всему миру
MVP-фокус: Базовый флоу без сложных фич (например, водяные знаки ).


2. Функциональные требования
2.1. Пользовательские роли

Художник: Регистрация профиля, прием заказов, отправка previews/full-res, подтверждение оплаты.
Заказчик: создание заказа, оплата, просмотр работ.
Админ (ты как разработчик): Мониторинг споров, бан пользователей, аналитика.

2.2. Основной флоу (workflow)

Регистрация: Команда /start → выбор роли (художник/заказчик) → ввод ника, контактов, подтверждение (без email, только TG-ID).
создание заказа: отправляет запрос нужному tg_id который уже зарегестрирован в боте → художник принимает/отклоняет.
Обсуждение деталей: Встроенный чат в боте или переход в приватный TG-чат.
Предпросмотр: Художник загружает low-res с водяными знаками (бот автоматически добавляет watermark: ID заказа + дата + ник) → отправка с protect_content=true + пояснительная записка отпралять 1:1 приватное медиа, для того чтобы нельзя было заскриншотить 
Оплата: Escrow-подход — заказчик платит боту (Stars/TON + деньги счет) → средства держатся до подтверждения → релиз художнику минус комиссия (10%).
Финальная передача: Бот создает приватный 1:1 чат → инструкция художнику отправить full-res как disappearing media (view-once или таймер 10–30 сек) → подтверждение просмотра от заказчика.
Завершение: Отзывы, релиз средств, логи для споров.
Dispute-система: Если спор — админ решает (возврат/релиз средств).

2.3. Ключевые фичи

Защита ИС:
Protect_content=true для всех медиа от бота.
Автоматические водяные знаки (библиотека Pillow: overlay текст/ID).
Инструкции по disappearing media (текст + изображения гайда).

Платежи:
Telegram Stars для микроплатежей (sendInvoice/sendPaidMedia).
TON для крупных (интеграция с TON Wallet API).
Escrow: Деньги на твоем аккаунте/кошельке до подтверждения (с рисками, см. правила).

Монетизация:
10% комиссия по умолчанию.
Премиум-подписка: 300 руб./мес. (без комиссии ).
ТГ-канал: @ArtSecureNews для новостей, рекламы.

Дополнительно:
NDA-генератор: Бот создает PDF с шаблоном (библиотека reportlab).
Чёрный список: База скамеров (по отзывам).
Аналитика: Кол-во заказов, доход (Google Analytics или встроенная).


2.4. Интерфейс

Inline-кнопки для навигации 
Текстовые инструкции с эмодзи для ясности.
Локализация: Все большинство языков

2.4. Команды

/start - начало открытие и выбор (Заказчик или Исполниьель)
/rules - правила для каждого участника
/report - пожаловаться на пользователя 
/help - поддержка перехо к чату с поддержкой
/my_orders - мои созданные заказы и данные(готовый, ожидание, можно удалить заказ)
/create - создание заказа (Название, цена, оплата, /search)
/search - поиск исполнителя
/send_art - отправить арт



3.2. Безопасность

Хранение данных: Только необходимые (TG-ID, заказы) — GDPR-compliant.
Защита от спама: Rate-limiting .
Escrow: Не держать >100к руб. на аккаунте; использовать внешний сервис при росте.
Риски: Уведомление пользователей о не 100% защите (скриншоты возможны).

3.3. Надёжность

Uptime: 99% (мониторинг с UptimeRobot).
Бэкапы БД: Ежедневно.

3.4. Совместимость

Telegram: Поддержка мобильных, десктоп, веб.
ОС: Android/iOS для disappearing (уведомление в интерфейсе).

4. Технологический стек
4.1. Backend

Язык: Python 3.10+ (простота, библиотеки для TG).
Фреймворк для бота: aiogram 3.x (асинхронный, удобный для inline/кнопок) или python-telegram-bot (синхронный, проще для новичка).
База данных: SQLite для MVP (бесплатно, локально) → PostgreSQL для продакшена (Heroku/Supabase).
Обработка изображений: Pillow для водяных знаков.
PDF-генерация: Reportlab или FPDF.
Платежи: Telegram Bot API (Stars) + TON SDK (ton-python).

4.2. Frontend

Нет отдельного; всё через Telegram UI (inline-кнопки, меню).

4.3. Инфраструктура

Хостинг: VPS (Hetzner, DigitalOcean) или облако (AWS Lightsail, ~500 руб./мес.).
CI/CD: GitHub Actions для деплоя.
Мониторинг: Logging с Sentry или встроенный в код.
API: Telegram Bot API (бесплатно).

4.4. Библиотеки

aiogram/telebot: Основной.
SQLAlchemy: ORM для БД.
aiohttp: Для асинхронных запросов (TON API).
python-dotenv: Для env-файлов (токены).



6. Основные правила и политики
6.1. Правила для пользователей

Запрет кражи ИС: Автоматическое предупреждение + бан за жалобы.
Комиссия: 10% — прозрачно в интерфейсе.
Споры: 7 дней на разрешение админом.

6.2. Юридические аспекты

Оферта: Пользователи соглашаются при /start.
Ответственность: Бот не гарантирует 100% защиту; рекомендуй NDA.
Монетизация: Соответствие законам РФ (115-ФЗ для платежей).

6.3. Разработка правила

Code style: PEP8.
Версионирование: Git.
Тестирование: Pytest для unit-тестов.

7. Тестирование

Unit-тесты: Функции (водяные знаки, платежи).
Интеграционные: Полный флоу с тестовыми аккаунтами.
Ручное: На разных устройствах (Android, iOS, ПК).
Load-тест: 100 симуляций сообщений.

8. Развертывание и поддержка

Деплой: Docker для контейнеризации → VPS.
Мониторинг: Logs в файл + Telegram-уведомления об ошибках.
Обновления: Еженедельно для фидбека.
Поддержка: Чат в боте для пользователей.

9. Риски и mitigation

Риск бана бота: Соблюдать ToS Telegram (нет спама).
Риск кражи: Документировать, что disappearing — не 100%.
Риск платежей: Начать с малых сумм; перейти на внешний escrow.s
